LLM 原始数据优化 (Prompt Engineering)

让 LLM 更轻松地理解 PDF 结构

现状：原始碎块 (Unoptimized)
[ID: 1, Type: Line, Box: [10, 10, 15, 80]] "1. Introduction"
[ID: 2, Type: Line, Box: [20, 10, 25, 90]] "Deep learning is a subset"
[ID: 3, Type: Line, Box: [26, 10, 31, 85]] "of machine learning..."
[ID: 4, Type: PageNum, Box: [950, 480, 970, 520]] "Page 1"
⚠️ 痛点：Token 浪费，包含页码干扰，知识点被切断。
优化：预聚合语义块 (Optimized)
[ID: P1, Type: Title] "1. Introduction"
[ID: P2, Type: Paragraph] "Deep learning is a subset of machine learning..."
✅ 优点：语义完整，去除冗余（页码、坐标细节），LLM 逻辑关联更稳健。

优化策略：

  • 前端聚类 (Pre-Processing)：在调用 API 前，利用 Azure 返回的 paragraph 信息，将零散的 lines 合并为单一的 block。
  • 坐标归一化：将复杂的坐标转化为 LLM 易理解的 0-1000 比例值，并仅在需要时输出。
  • 上下文增强：在 Prompt 中明确告诉 LLM：“你现在的任务是为每个知识点选择最匹配的 Block IDs”。

您是否同意我们在发送给 LLM 之前，先在前端/后端做这一层“语义预合并”？
