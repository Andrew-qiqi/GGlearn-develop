# GGlearn 教材正文质量优化设计

## 1. 文档目的

本设计用于重新定义 GGlearn 教材生成系统的第一优先级：生成一份用户愿意读、能学会、并且自然信任的教材正文。

当前系统已经具备来源资产、证据包、章节生成和互动学习等基础能力，但教材正文仍容易显得粗糙：内容像资料摘要，章节主线不够清晰，例题与练习像外部组件，来源依据在用户面前存在感过强。

本次优化的核心不是继续强化 citation 展示，而是把 citation、source refs、evidence packs 和 validation 明确放回后台质量层，让用户前台看到的是连续、清晰、教学感强的教材。

## 2. 设计结论

GGlearn 的教材生成应从“资料驱动的 chunk 卡片流”转向“后台 grounded、前台连续正文”的教材系统。

核心结论如下：

- 教材生成阶段产生的一切内容都属于教材正文，包括概念讲解、定义、推导、图解说明、例题、练习、常见误区、小结和掌握检查。
- 用户阅读时应看到连续教材，而不是一组松散卡片或资料组件。
- 用户后续触发的问答、笔记、手写批注、补充解释和重写结果才属于互动学习层。
- citation、source refs、evidence packs 和 validation 是后台质量机制，默认不作为用户阅读体验的一部分。
- 保留现有学习目标选择，但让 `mastery / exam / micro` 成为生成策略，而不是 prompt 中的一句风格提示。
- 第一版重点优化正文质量，不重做完整教材编辑器，不引入新依赖，不扩大成课程知识图谱系统。

## 3. 内容分层

### 3.1 教材正文层

教材正文层由教材生成阶段产生，是用户阅读的主内容。

它包括：

- 概念讲解
- 定义
- 推导
- 图解说明
- 例题
- 练习
- 常见误区
- 小结
- 掌握检查

这些内容内部可以继续用 chunk、section 或 body block 管理，但用户体验上都应属于同一本连续教材。

例题和练习不是互动组件。它们只要是在教材生成阶段生成出来的，就属于正文。

### 3.2 互动学习层

互动学习层由用户阅读后触发或添加。

它包括：

- 用户提问
- AI 旁注回答
- 用户笔记
- 手写批注
- 局部解释
- 局部重写结果
- 学习进度

这一层叠加在教材正文之上，不应和原始教材正文混淆。后续实现中，互动产物不应直接污染教材正文的原始 chunk 集合。

### 3.3 来源依据层

来源依据层属于后台质量机制。

它包括：

- `sourceRefs`
- `evidencePacks`
- citation
- grounding metadata
- validation warnings

这一层用于约束生成、校验事实边界、支持内部追溯和未来调试。默认情况下，用户不需要看到来源依据，也不应该被迫检查依据。

用户需要信任教材，而不是替系统审稿。

## 4. 生成主链路

当前链路大致是：

```text
来源资产 -> evidence packs -> 一次性生成整章 chunks
```

新的链路应调整为：

```text
来源资产
-> 后台证据整理
-> 章节教学蓝图
-> 小节级正文生成
-> 后台质量校验
-> 连续教材渲染
```

### 4.1 后台证据整理

系统先整理可用资料，判断哪些内容可以支持本章，哪些内容不适合展开。

这一阶段不面向用户展示，不输出来源报告。它服务后续教学规划和质量控制。

### 4.2 章节教学蓝图

生成正文前，系统先规划这一章怎么教。

蓝图需要回答：

- 本章学习目标是什么
- 读者进入本章前默认处于什么状态
- 先讲什么，后讲什么
- 每个小节承担什么教学任务
- 哪些地方资料不足，应该谨慎处理

蓝图是后台教学计划，不是用户必须阅读的内容。

### 4.3 小节级正文生成

系统按教学蓝图逐节生成正文。

每一节只处理自己的教学任务，例如建立直觉、给出定义、展开推导、讲例题、做总结。这样可以避免整章一次生成时出现主线混乱和资料拼接感。

### 4.4 后台质量校验

生成后检查：

- 是否偏离教学蓝图
- 是否有明显 unsupported claims
- 是否跳过前置概念
- 是否过度暴露来源痕迹
- 是否像教材正文，而不是资料摘要

校验结果默认不展示给用户，只用于内部修复、重生成或标记风险。

### 4.5 连续教材渲染

阅读页应把生成结果渲染成连续教材。

内部仍然可以保留 chunk 边界，用于局部重生成、问答、笔记和学习进度，但视觉上不应表现成松散卡片流。

## 5. 学习目标如何影响正文

保留现有学习目标选择，但重新定义它在生成系统中的作用。

`mastery / exam / micro` 应成为后台生成策略，决定教学节奏、正文栏目密度、练习比例和解释深度。

### 5.1 `mastery`：掌握型教材

目标是让用户真正理解一套知识，而不是只记结论。

正文特征：

- 先建立问题意识和直觉
- 再给出定义、条件、边界
- 适当展开推导或机制解释
- 例题服务理解，不只是刷题
- 小结可以集中在章节末，避免频繁打断正文
- 练习适中，偏理解检验

生成节奏：

```text
动机 -> 直觉 -> 概念建立 -> 正式定义 -> 推导/解释 -> 例题 -> 练习 -> 总结
```

### 5.2 `exam`：考试型教材

目标是帮助用户快速抓重点、会做题、避开常见错误。

正文特征：

- 重点和题型更显式
- 常见误区、易混概念、解题步骤更突出
- 练习和掌握检查更多
- 仍然保留必要定义和边界，避免变成口诀堆砌

生成节奏：

```text
考点定位 -> 核心定义 -> 典型题型 -> 解题方法 -> 易错点 -> 练习 -> 速记总结
```

### 5.3 `micro`：短主题教材

目标是快速理解一个窄主题。

正文特征：

- 不展开完整课程结构
- 直觉、核心概念、一个例子或小练习
- 总结短而明确
- 不生成过多栏目，避免内容被切碎

生成节奏：

```text
为什么重要 -> 核心解释 -> 例子/应用 -> 掌握检查
```

### 5.4 其他用户设定

`priorKnowledgeLevel` 和 `explanationPreference` 继续保留，但它们用于调节比例，而不是另起一套生成模式。

- 基础越弱，直觉、例子、过渡越多。
- 基础越强，定义、推导、边界越早出现。
- `intuitive` 更偏老师讲解。
- `rigorous` 更偏教材严谨。
- `example-first` 更早进入例子。
- `textbook` 更平衡、连续。

## 6. 内部结构与前台呈现

第一版不需要立刻废弃现有 `Chunk`，但应调整语义。

系统内部可以逐步转向：

```text
Chapter
  Section
    BodyBlock
```

- `Chapter`：章节。
- `Section`：小节，对应教学蓝图中的一个教学任务。
- `BodyBlock`：正文片段，可能是讲解、定义、例题、练习、总结等。

每个正文片段可以有后台角色：

```ts
type ContentRole =
  | 'motivation'
  | 'intuition'
  | 'concept'
  | 'definition'
  | 'derivation'
  | 'worked-example'
  | 'practice'
  | 'common-mistake'
  | 'summary'
  | 'mastery-check';
```

这些角色不等于前台组件类型。它们主要服务：

- 生成约束
- 质量检查
- 局部重生成
- 后续互动定位
- 阅读进度统计
- 未来导出或复习资产提取

前台阅读页应更像：

```text
第 1 章 标题

1.1 小节标题

连续正文……
例题……
继续解释……
小练习……
过渡到下一节……

1.2 小节标题

连续正文……
```

而不是：

```text
[概念卡片]
[图表卡片]
[练习卡片]
[总结卡片]
```

这不代表不能有排版区分。例题、练习、常见误区可以有轻微视觉样式，但它们仍然嵌在正文流里，不应该像独立工具组件或外部插件。

## 7. 生成策略

第一版建议把生成入口调整为：

```text
generateChapter(...)
  -> buildEvidencePacks(...)
  -> createChapterBlueprint(...)
  -> generateSectionsFromBlueprint(...)
  -> validateGeneratedChapter(...)
  -> return body chunks for rendering
```

### 7.1 Chapter Blueprint

蓝图负责教学顺序，不负责写正文。

建议结构：

```ts
interface ChapterBlueprint {
  chapterTitle: string;
  chapterGoal: string;
  targetReaderState: string;
  teachingProfile: TeachingProfile;
  sections: ChapterSectionBlueprint[];
  unsupportedGaps: string[];
}
```

每个 section 包含：

```ts
interface ChapterSectionBlueprint {
  id: string;
  title: string;
  teachingRole: ContentRole;
  dependsOnSections: string[];
  focusConcepts: string[];
  transitionFromPrevious: string;
  expectedBodyRoles: ContentRole[];
}
```

`expectedBodyRoles` 根据 `mastery / exam / micro` 变化。比如 `exam` 更容易包含 `common-mistake`、`practice`、`mastery-check`，`mastery` 更容易包含 `derivation`、`definition`、`worked-example`。

### 7.2 Section 级正文生成

每次只生成一个 section 的正文，输入包括：

- 当前章节目标
- 当前小节教学任务
- 前文已经解释过的概念
- 上一节的真实摘要
- 后台选出的 evidence packs
- 写作契约

写作契约应明确：

- 必须像教材正文
- 不得写成来源摘要
- 不得暴露“根据资料”“本文指出”等来源痕迹
- 必须完成当前 section 的教学职责
- 可以弱化资料不足处的断言，但不能编造细节

每个 section 生成若干 `BodyBlock`，再兼容映射回现有 `Chunk`。

### 7.3 后台质量校验

第一版校验可以先做轻量规则和模型自检，不做复杂评分系统。

校验重点：

- 是否把来源依据写成“根据资料”“本文指出”等来源泄露式表达
- 是否有明显空泛段落
- 是否跳过必要铺垫
- 是否没有完成 section 的教学职责
- 是否出现缺乏依据的强断言
- 是否像正文，而不是卡片清单

校验结果不进入主阅读 UI。

### 7.4 失败处理

不要在前台直接告诉用户“证据不足”。

后台应把资料不足转成生成策略：

- 资料不足的内容，只做概念性解释，不展开具体结论。
- 不能支撑的推导，不强行生成。
- 如果整章资料明显不足，正文里自然降低断言强度。
- 后台记录 validation warning，未来可用于提示用户补充资料，但不打断阅读体验。

## 8. 第一版落地边界

第一版只做一件事：让生成出来的教材正文明显更像可读、可学、可信任的教材。

### 8.1 保留

- 保留当前创建项目流程。
- 保留现有学习目标选择：`mastery / exam / micro`。
- 保留来源资产处理链路。
- 保留内部 `chunks` 存储，避免一次迁移太大。
- 保留局部重生成、提问、笔记等现有互动能力。

### 8.2 修改

- 新增教学画像 `TeachingProfile`，由学习目标、基础水平、讲解偏好生成。
- 新增 `ChapterBlueprint`，先规划章节教学顺序。
- 新增 section-by-section 正文生成。
- 新增后台 validation。
- 生成结果仍映射为 chunk，但 chunk 语义从“卡片类型”转为“正文片段”。
- 阅读页从卡片流调整为连续教材流。
- 例题、练习、总结、误区提醒作为正文段落显示。
- 默认隐藏 citation、source refs 和 evidence 信息。

### 8.3 暂不做

- 不做复杂课程知识图谱。
- 不引入向量数据库。
- 不新增依赖。
- 不做完整所见即所得教材编辑器。
- 不把 citation 设计成前台重点功能。
- 不做复杂质量评分面板。
- 不把所有历史数据一次性迁移成新结构。

## 9. 与已有两阶段设计的关系

仓库中已有 `2026-04-19-gglearn-textbook-generation-two-stage-design.md`，其“教学蓝图先行、逐节生成、轻量校验”的方向仍然成立。

本设计在其基础上补充并修正产品边界：

- citation 和 source grounding 应进一步后移到后台质量层。
- 前台默认不展示来源依据。
- 教材生成产物全部视为正文，不再把练习、总结、图解切成外部组件。
- 阅读页目标应从 chunk 卡片流转为连续教材正文。
- 学习目标选择应成为生成策略，而不是仅影响 prompt 文风。

因此，后续实现计划应以原两阶段技术路线为基础，但以本设计中的内容分层和前台呈现规则作为产品约束。

## 10. 成功标准

第一版完成后，应满足：

- 同一章读起来有清晰主线，而不是资料片段拼接。
- 正文先建立直觉，再进入定义、推导、例题、练习和总结。
- `mastery / exam / micro` 的差异体现在教学节奏和栏目密度上。
- 例题、练习、总结等生成内容属于正文流，而不是外部组件。
- 阅读页默认不突出 citation、source refs 或 evidence 信息。
- 后台仍保留 grounding 和 validation，用于质量控制。
- 现有互动能力继续作为阅读后的学习层存在。

## 11. 自检

- 没有未决空白项。
- 本设计聚焦教材正文质量，没有扩大到完整课程编辑器。
- citation 的定位明确为后台质量机制，不再作为前台主叙事。
- 第一版保留现有数据结构与入口，降低迁移风险。
- 与已有两阶段生成设计不冲突，而是补充产品边界和正文语义。
