# GGlearn 产品功能主叙事与资料流转设计

## 1. 文档目的

本设计用于重新定义 GGlearn 的产品语言与全局功能骨架。

目标不是补充更多实现细节，而是解决当前讨论中的几个核心偏差：

- 不再用一长串内部对象名主导产品理解
- 不再把 source grounding 误解为前端 citation 产品
- 不再把来源直接等同于可信教材依据
- 不再让“资料原话”污染教科书正文

本设计产出一套更稳定的顶层描述，用于后续模块重构、实现规划与体验决策。

## 2. 一句话定义

GGlearn 是一个由 **系统设置** 统一控制、围绕 **原始资料获取、资料处理、生成教材、用户互动、学习资产后处理** 运转的教材生成与学习系统。

## 3. 全局功能骨架

GGlearn 的全局模型应被拆成两部分理解：

- `系统设置` 是贯穿全局的控制层
- `原始资料获取 -> 资料处理 -> 生成教材 -> 用户互动 -> 学习资产后处理` 是主链条

因此，系统设置不只是一个孤立页面，而是决定整个系统如何运转的前置条件。

### 3.1 系统设置

系统设置是 GGlearn 的全局控制层。

它负责定义系统在后续各阶段中的运行方式，包括但不限于：

- 界面语言
- AI provider
- API key
- OpenAI compatible base URL
- 默认模型
- 后续可扩展的处理强度、生成风格、资料处理策略

系统设置会直接影响：

- 原始资料获取
  - 能否执行联网搜索
  - 使用哪种模型进行搜索辅助
- 资料处理
  - 使用哪种模型做来源 enrichment
  - 处理输出的语言
- 生成教材
  - 使用哪种模型生成教材
  - 教材输出语言与风格倾向
- 用户互动
  - Explain / Ask AI 的可用性与表现

这一层的关键原则：

- 系统设置不是普通链条节点，而是链条的全局控制条件
- 设置变化会影响后续多个阶段
- 产品上应把它视为“控制台”，而不只是“设置页”

### 3.2 原始资料获取

原始资料获取是 GGlearn 的输入层。

用户可以通过以下方式把资料带入项目：

- 上传 PDF
- 上传图片
- 输入 URL
- 通过网络搜索引入网页结果
- 后续可扩展为视频、音频、文档等

这一层的关键原则：

- 原始资料只是输入，不等于教材依据
- 原始资料可能可信，也可能不可信
- 原始资料可能完整，也可能只是片段或摘要
- 系统不能默认把原始资料直接用于教材生成

#### 3.2.1 原始资料获取的职责边界

原始资料获取要解决的问题不是“如何理解资料”，而是“如何把资料稳定、清晰、可扩展地带进系统”。

这一层应只承担以下职责：

- 提供资料入口
- 获取资料正文或原始文件
- 建立项目内原始资料记录
- 标记获取状态
- 保留来源路径与 provenance

这一层不应承担以下职责：

- 可信度判断
- 教学价值判断
- 教材适配判断
- 证据抽取
- 教材生成

也就是说，原始资料获取解决的是“拿进来”和“记清楚”，而不是“判断能不能用”。

#### 3.2.2 候选线索与原始资料的区分

GGlearn 应明确区分两个概念：

- `候选线索`
- `原始资料`

候选线索指：

- 搜索结果页中的 snippet
- 搜索命中的标题与摘要
- 尚未抓到正文的网页命中项

原始资料指：

- 已成功上传的本地文件
- 已成功抓取正文的 URL 页面
- 已成功获取可解析内容的网页或远程资源

关键规则：

- 网络搜索结果默认只是候选线索
- 只有抓到正文或可解析内容后，才升级为原始资料

这个边界必须固定，因为如果把搜索 snippet 直接视为原始资料，整个链条会从源头引入不完整和误导性输入。

#### 3.2.3 原始资料获取的标准入口

第一阶段建议将原始资料获取的入口明确为三类：

- `文件导入`
  - PDF
  - 图片
  - 后续可扩展文档格式
- `直接 URL 导入`
  - 用户明确提供 URL
  - 系统尝试抓取正文
- `网络搜索`
  - 先返回候选线索
  - 再由系统或用户触发正文抓取
  - 成功抓取后才入原始资料库

这三类入口在产品上可以共存，但语义必须不同：

- 文件导入与成功抓取的 URL 导入，直接产生原始资料
- 网络搜索默认先产生候选线索

#### 3.2.4 原始资料获取的状态模型

为了让后续资料处理知道自己接到的是什么，原始资料获取至少需要以下状态：

- `候选线索`
- `待抓取`
- `抓取中`
- `已获取`
- `获取失败`
- `仅命中摘要`

其中：

- `候选线索` 和 `仅命中摘要` 不能直接进入教材生成
- 只有 `已获取` 才能进入资料处理主流程

#### 3.2.5 原始资料获取的最小模块划分

这一层在产品和系统上都建议拆成四个小模块：

- `资料入口层`
  - 上传、URL 输入、搜索入口
- `候选线索层`
  - 承接搜索命中项
- `正文获取层`
  - 真正负责抓取页面内容或下载文件
- `原始资料登记层`
  - 把成功获取的内容记录为项目内原始资料

这样设计的好处是：

- 不会把“搜索命中”误当成“资料本体”
- 资料来源路径更清晰
- 失败状态可见
- 后续资料处理可以更干净地接入

### 3.3 资料处理

资料处理是 GGlearn 的核心能力层。

它负责把原始资料转换成可用于教材生成的内部依据资产。处理内容包括：

- 文本抽取
- 结构识别
- 锚点定位
- 噪声清洗
- 概念提取
- 检索单元切分
- 证据片段整理
- 可信度判断
- 教学价值判断
- 使用角色判断

这一层的目标不是把资料“总结给用户看”，而是把资料转成系统可控、可筛选、可重组、可约束生成的教学输入。

### 3.4 生成教材

生成教材是 GGlearn 的主要输出层。

系统基于处理后的资料，而不是基于原始资料直接生成教材。教材生成的核心原则如下：

- 输出必须教学化，而不是资料转述
- 输出必须结构化，而不是检索拼接
- 输出必须可信，但不能带有明显来源搬运口吻
- 输出必须适合学习，不是问答式引用展示

这里特别需要固定一条边界：

- source grounding 的第一目标是提升教材生成质量与可信度，而不是让用户点击 citation 回溯来源

### 3.5 用户互动

用户互动发生在教材生成之后，是用户与教材的学习环节。

包括：

- 阅读教材
- 章节导航
- Ask AI / Explain
- 记笔记
- 手写标注
- 局部重生成
- 章节续写

这一层的重点是帮助用户理解教材内容，而不是让用户直接面向原始资料。

### 3.6 学习资产后处理

学习资产后处理是 GGlearn 的沉淀层。

它负责把教材阅读与互动过程中产生的新内容转化为长期可用的学习资产，包括：

- 学习笔记
- 手写记录
- 解释性补充块
- 章节修订结果
- 练习结果
- 后续可扩展为错题、卡片、摘要、复习计划

这一层意味着 GGlearn 不只是一次性生成教材，而是持续生成、积累和重组学习资产。

## 4. 顶层产品模型

为了降低产品心智复杂度，GGlearn 的产品层应保留三类顶层概念：

### 4.1 系统设置

系统设置是全局控制层。

它不属于资料本身，也不属于教材本身，而是负责控制链条如何运行。

建议产品上至少区分三类设置：

- 全局系统设置
  - 界面语言
  - provider
  - API key
  - base URL
  - 默认模型
- 项目设置
  - 教材语言
  - 学习模式
  - custom focus
- 运行时设置
  - 某次生成使用的模型
  - 某次搜索是否开启
  - 资料处理严格度
  - 教学化强度与 grounding 强度

当前第一阶段尚未完全显式拆开这三类，但产品设计上应保留这个方向。

### 4.2 原始资料

原始资料是用户带进系统的输入物。

定义：

- 尚未被系统判断
- 尚未被系统教学化
- 尚未被系统正式准入为教材依据

它的定位是：

- 待处理的输入
- 待判断的候选材料
- 而不是默认可信真理

### 4.3 资料处理

资料处理是系统将原始资料转化为教材依据资产的全过程。

定义：

- 它不是单一步骤
- 它是一组内部流水线
- 它的结果是“可用于教材生成的内部资产”

产品层只需要理解：

- 原始资料进入系统
- 系统完成资料处理
- 教材生成只消费处理后的结果

## 5. 内部对象与产品语言的映射

当前代码中的内部对象仍然有价值，但它们应退居实现层。

### 5.1 建议映射

- `SourceDocument`
  - 产品语义：原始资料输入
- `ProjectSource`
  - 产品语义：项目内原始资料记录
- `ProjectSourceSnapshot`
  - 产品语义：资料处理中的结构化抽取结果
- `ProjectSourceAsset`
  - 产品语义：已处理资料 / 教材生成依据资产
- `EvidencePack`
  - 产品语义：生成阶段的临时证据视图，不是独立产品对象

### 5.2 对外原则

对用户和产品文档：

- 尽量使用“原始资料”“已处理资料”“教材生成依据”

对系统内部：

- 仍可保留当前对象链以支持实现稳定性

## 6. 当前模块与全局功能的对应关系

### 6.1 Dashboard

当前职责：

- 展示项目列表
- 展示 source readiness、grounding 等摘要

建议产品语义：

- 项目库

### 6.2 Project Creator

当前职责：

- 创建项目

建议产品语义：

- 项目设定

### 6.3 Source Workspace

当前职责：

- 上传 PDF / 图片
- 输入 URL
- 网络搜索
- 选择 source
- 删除 source
- 触发教材生成

建议产品语义：

- 原始资料与资料处理工作台

未来不应只承担“上传来源”的职责，还应承担：

- 资料质量判断
- 准入判断
- 角色分配
- 使用策略展示

### 6.4 Reader

当前职责：

- 阅读 chunk

### 6.5 Settings

当前职责：

- 模型与语言设置

建议产品语义：

- 系统控制台

- 影响资料获取
- 影响资料处理

- 影响用户互动

## 7. 当前信息流

从产品角度，当前系统不应只被理解为线性六步，而应拆成：

- 一个控制层：系统设置
- 一条主链条：项目设定 -> 原始资料获取 -> 资料处理 -> 生成教材 -> 用户互动 -> 学习资产后处理

### 7.1 当前主流程

从产品角度，当前系统应被概括为以下流程：

1. 用户配置系统设置
2. 用户创建项目
3. 用户导入原始资料
4. 系统执行资料处理
5. 系统基于处理后的资料生成教材
6. 用户围绕教材进行互动
7. 互动结果沉淀为新的学习资产

在这个流程里，原始资料获取内部还应再细分为：

1. 资料入口
2. 候选线索形成
3. 正文或文件获取
4. 原始资料登记

其中只有第 4 步的结果才能正式流入资料处理。

### 7.2 当前实现层说明

从实现角度，当前代码内部存在更细的对象链，但不应成为产品主叙事。

同时需要注意：

- 当前设置中的语言、provider、模型与 API key 已经真实影响多个阶段
- 因此后续产品文档不应再把系统设置写成“附属模块”

## 8. 对 source 的重新定义

GGlearn 中的 source 不应再被理解为“默认可信的教材依据”，而应被理解为：

- 待处理的候选资料
- 待判断的输入材料
- 可能可靠，也可能不可靠
- 可能适合教学，也可能不适合教学

因此，source 的真实产品角色是：

- 不是“证据本身”
- 而是“候选证据对象”

只有在资料处理完成后，系统才应决定：

- 这份资料能否进入教材生成
- 这份资料适合扮演什么角色
- 这份资料应该被强使用、弱使用，还是排除使用

## 9. 资料处理中的判断任务

资料处理至少应承担两种判断：

### 9.1 可信度判断

系统需要判断：

- 来源是否可靠
- 内容是否完整
- 是否存在明显噪声
- 是否存在误导性表达
- 是否只是搜索摘要而非全文

### 9.2 教学价值判断

系统需要判断：

- 是否适合解释概念
- 是否适合提供直觉
- 是否适合支撑定义
- 是否适合支撑推导
- 是否适合支撑例子
- 是否只适合作为背景材料

这意味着资料处理不只是“结构化抽取”，而是“为教材生成做准入与分工”。

## 10. 教材生成的边界

### 10.1 教材不应等于资料转述

过度强调 source grounding，容易把正文写成资料重述或资料摘要。

这是 GGlearn 明确要避免的方向。

教材生成必须满足：

- 以教师口吻组织内容
- 用教学逻辑重写知识
- 吸收来源，而不是模仿来源

### 10.2 教材正文默认禁止来源泄露式表达

教材正文不应默认出现以下表述：

- “正如某作者所展示的”
- “根据某视频/某论文”
- “3Blue1Brown 认为”
- 其他明显把来源名直接暴露给正文的写法

原因：

- 这会让教材退化为资料导览
- 会破坏教材叙述的统一性
- 会暴露模型在“搬运来源口吻”

### 10.3 grounding 的真正目标

grounding 的目标应被定义为：

- 提升教材事实可靠性
- 提升章节生成质量
- 为系统提供内部可审计性
- 支持局部重生成与质量回修

而不是：

- 默认做成前端 citation 点击系统

## 11. 当前最优先的问题

本轮对齐后，GGlearn 当前最优先解决的问题不是 citation UI，而是：

### 11.1 问题一：产品语言混杂

当前产品理解容易被内部对象链牵着走。

需要用“原始资料 / 资料处理 / 教材 / 用户互动 / 学习资产后处理”重新统一。

### 11.2 问题二：source 默认被当作可用依据

当前系统中，原始资料进入项目后较快被纳入教材生成流程。

需要补强“资料判断与准入”这一层。

同时，当前网络搜索结果也存在被过早视为资料输入的问题。

后续需要明确修正为：

- 搜索结果默认是候选线索
- 抓取正文成功后才成为原始资料

### 11.3 问题三：grounding 与教学化改写边界不清

当前系统更强调 evidence packs 的使用约束，但还缺少足够强的“教学化改写边界”。

需要明确：

- grounding 服务质量
- 教学化决定正文风格

### 11.4 问题四：Source Workspace 的职责过窄

它现在更像“来源上传页”。

未来应升级为：

- 原始资料接入
- 资料处理状态展示
- 资料质量判断
- 教材依据准入与编排

## 12. 后续设计方向

基于本设计，下一阶段建议围绕以下主题展开：

### 12.1 Source Evaluation / Admission

补充 source 的判断、准入与角色分配机制。

### 12.2 教学化改写边界

明确教材生成中哪些表达应该禁止，哪些表达应该鼓励。

### 12.3 Source Workspace 重定义

把它从“来源上传区”升级为“资料处理与准入工作台”。

### 12.4 学习资产后处理扩展

将用户互动产生的内容进一步结构化沉淀。

## 13. 结论

GGlearn 后续不应继续被描述为“上传 source 后生成内容”的系统。

更准确的定义应当是：

- 它先获取原始资料
- 再处理原始资料
- 再基于处理结果生成教学化教材
- 再围绕教材产生互动
- 最后把互动沉淀为长期学习资产

这五段链路是 GGlearn 后续产品、实现与文档的统一骨架。
